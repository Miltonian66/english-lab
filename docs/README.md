# Документация English Lab

`scope`: назначение проекта, индекс владельцев фактов, карта кода и общая проверка
`source_of_truth`: `README.md`, `english_bot/`, `tests/`, `deploy/`, `AGENTS.md`

## Назначение

English Lab — многопользовательская платформа изучения английского в Telegram для
одного отдела. Курс грамматики A1–C2 по темам, тренажёр с интервальным
повторением, адаптивная диагностика уровня, устная практика с расшифровкой,
разбор письма по четырём критериям и произношение с озвучкой.

Платформа не выдаёт сертификат CEFR и не оценивает реальное произношение: модель
работает с расшифровкой, а не со звуком.

## Проверенные факты

- Ядро — Python 3.11+ и только стандартная библиотека. Локальная речь —
  единственное исключение: `faster-whisper` и `piper-tts` в `.venv`.
- Контент: 221 пункт грамматики, 1768 упражнений, 708 слов, 60 устных и 36
  письменных заданий, 50 паттернов ошибок русскоязычных, 22 звука.
- Структура курса снята со структуры test-english.com; уровни A1–C2, внутри
  уровня темы, внутри тем правила.
- Курс, тренировка, повторение и диагностика работают без ключей и без сети.
- Текст можно питать подпиской Codex (бесплатно, 8–12 с на ответ) или API OpenAI
  и Anthropic (быстро, по токенам). Голос — локальными моделями или API.
  Контуры переключаются двумя переменными в `.env`, код при этом не меняется.
- Данные учеников изолированы; общая только таблица отдела, участие отключается.
- Имя для таблицы берётся из профиля Telegram: вводить его руками не нужно.
- Навигация кнопками: постоянная клавиатура внизу экрана, «🎯 Заниматься» сама
  выбирает занятие дня и запускает его без единого вопроса.
- Интерфейсы разделены: у действия ровно одна точка входа. Кнопки закрывают всё
  ежедневное, команд остаётся девять — только то, чего кнопкой не сделать.
- Схема SQLite версии 3; база личного бота версии 1 мигрирует без потери данных.

## Порядок чтения

- Поведение для ученика: этот индекс → `docs/product.md`.
- Учебный материал: этот индекс → `docs/content.md`.
- Интеграции, данные, deployment: этот индекс → `docs/operations.md`.
- Сквозное изменение: прочитать нужных владельцев, но каждый факт править только
  у одного.

## Карта проекта

| Путь | Роль |
|---|---|
| `english_bot/app.py` | маршрутизация, пул воркеров, контроль доступа |

| `tests/` | 207 автоматических проверок |
| `deploy/` | systemd user unit |

## Общая проверка

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q english_bot tests
python3 -m english_bot.content.validate
systemd-analyze --user verify deploy/english-tutor-bot.service
git diff --check
```

Успех: 207 тестов проходят (из системного `python3` шесть тестов локальной речи
пропускаются), компиляция без ошибок, валидатор контента печатает
`ошибок: 0`, unit-файл валиден, `git diff --check` молчит.

## Ограничения документации

- Staging-контура нет: живая проверка идёт на реальном боте.
- Ключи ответов и транскрипции выверены состязательным прогоном моделей, а не
  преподавателем-носителем; спорные случаи правятся в `english_bot/content/data/`.
- Аудирование как навык не покрыто ни контентом, ни сценарием.
- Стоимость обращений к внешним ИИ-сервисам документация не отслеживает:
  `DAILY_AI_CALLS` ограничивает количество, но не цену.

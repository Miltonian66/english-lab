# Документация English Lab

`scope`: назначение проекта, индекс владельцев фактов, карта кода и общая проверка
`source_of_truth`: `README.md`, `english_bot/`, `tests/`, `deploy/`, `scripts/`, `.github/workflows/`, `AGENTS.md`

## Назначение

English Lab — многопользовательская платформа изучения английского в Telegram для
отдела АБП. Курс грамматики A1–C2 по темам, тренажёр с интервальным повторением,
адаптивная диагностика уровня, аудирование, устная практика с расшифровкой,
разбор письма по четырём критериям, произношение с озвучкой и справочный
ИИ-ассистент по возможностям самой платформы.

Платформа не выдаёт сертификат CEFR и не оценивает реальное произношение: модель
работает с расшифровкой, а не со звуком.

## Проверенные факты

- Ядро — Python 3.11+ и только стандартная библиотека. Локальная речь —
  единственное исключение: `faster-whisper` и `piper-tts` в `.venv`.
- Контент: 221 пункт грамматики, 2444 упражнения, 735 слов, 60 устных, 54
  письменных и 60 заданий на аудирование, 50 паттернов ошибок русскоязычных,
  22 звука.
- Структура курса снята со структуры test-english.com; уровни A1–C2, внутри
  уровня темы, внутри тем правила.
- Курс, тренировка, повторение и диагностика работают без ключей и без сети.
- Текст можно питать подпиской Codex (8–12 с на ответ) или подпиской Claude
  (4–8 с) — обе без ключа и без денег — либо API OpenAI и Anthropic (быстро, по
  токенам). Голос — локальными моделями или API. Контуры переключаются двумя
  переменными в `.env`, код при этом не меняется.
- Данные учеников изолированы; общая только таблица отдела, участие отключается.
- Имя для таблицы берётся из профиля Telegram: вводить его руками не нужно.
- Навигация кнопками: постоянная клавиатура внизу экрана, «🎯 Заниматься» сама
  выбирает занятие дня и запускает его без единого вопроса; недоступный контур
  она не предлагает.
- Начатое занятие не пропадает: «📚 Курс» и «📊 Я» его не трогают, «🎯 Продолжить»
  возвращает к текущему вопросу, а переключение на другой вид спрашивает.
- Любая функция главной клавиатуры и экрана «📊 Я» стартует не больше чем за два
  нажатия; каталог курса — явное исключение с кнопкой «Продолжить» и `/learn`.
- `/help <вопрос>` ищет релевантные статьи в локальной базе знаний и просит LLM
  сформулировать grounded-ответ; `/help` без вопроса остаётся статическим.
- Обновления разных пользователей обрабатываются параллельно без фиксированных
  дорожек; LLM, Whisper и Piper изолированы в отдельных ограниченных пулах.
- Длинная работа вынесена из дорожки обновлений в фоновые задачи — по одной на
  человека, с отменой по `/stop`. Во время расшифровки голосового кнопки и
  команды отправителя продолжают работать.
- Интерфейсы разделены: у действия ровно одна точка входа. Кнопки закрывают всё
  ежедневное, команд остаётся десять — только то, чего кнопкой не сделать.
- Схема SQLite версии 5; база личного бота версии 1 мигрирует без потери данных.
- Прод работает из главного worktree репозитория на `main`. Изменение попадает
  туда только через ветку, PR, зелёный CI и `scripts/release.sh deploy`.

## Порядок чтения

- Любая задача с изменениями: `AGENTS.md`, раздел «Git, worktree и выкладка», затем
  нужный владелец ниже.
- Поведение для ученика: этот индекс → `docs/product.md`.
- Учебный материал: этот индекс → `docs/content.md`.
- Интеграции, данные, сервис: этот индекс → `docs/operations.md`.
- Ветки, CI, выкладка на прод, откат: этот индекс → `docs/delivery.md`.
- Сквозное изменение: прочитать нужных владельцев, но каждый факт править только
  у одного.

| `english_bot/ai/` | провайдеры текста (HTTP, Codex и Claude по подписке), речь хостинговая и локальная, промпты |
| `.venv/`, `data/models/` | зависимости и модели локальной речи, вне Git |

| `tests/` | автоматические проверки |
| `deploy/` | systemd user unit |
| `scripts/` | `check.sh` — общая проверка, `worktree.sh` — рабочие копии, `release.sh` — выкладка и контроль расхождения |

| `.githooks/` | запрет коммита и push в `main` |

## Общая проверка

```bash
scripts/check.sh
scripts/release.sh status
```

Успех: `check.sh` прогоняет весь набор тестов, компиляцию, валидатор контента
(`ошибок: 0`), проверку пробелов и unit-файла и заканчивает строкой
`check: всё зелёное`; `status` завершается с кодом 0 — прод совпадает с
`origin/main`. Состав шагов — `docs/delivery.md`.

## Ограничения документации

- Ключи ответов и транскрипции выверены состязательным прогоном моделей, а не
  преподавателем-носителем; спорные случаи правятся в `english_bot/content/data/`.
- Аудирование синтетическое: диалоги звучат двумя голосами Piper, но живые
  записи, фоновые шумы и акценты не покрыты.
- Стоимость обращений к внешним ИИ-сервисам документация не отслеживает:
  `DAILY_AI_CALLS` ограничивает количество, но не цену.

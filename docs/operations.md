# Эксплуатация, данные и интеграции

`scope`: конфигурация, доступ, внешние сервисы, схема данных, миграции, запуск и удаление
`source_of_truth`: `english_bot/config.py`, `english_bot/storage.py`, `english_bot/telegram_api.py`, `english_bot/ai/`, `english_bot/app.py`, `.env.example`, `deploy/english-tutor-bot.service`, `tests/test_storage.py`

## Назначение

Операционный контракт платформы. Учебный сценарий — в `docs/product.md`, состав
материала — в `docs/content.md`.

## Факты

- Ядро платформы — Python 3.11+ и только стандартная библиотека: HTTP-клиенты и
  multipart собраны на `urllib`, внешних пакетов ядро не требует.
- Локальная речь — единственное исключение: `faster-whisper` и `piper-tts` живут в
  `.venv` и импортируются лениво. С системным `python3` бот запускается, просто с
  выключенным голосом.
- Один процесс: long polling раскладывает апдейты по `WORKERS` однопоточным
  дорожкам (по умолчанию 4). Человек всегда попадает в одну дорожку по остатку
  от деления его Telegram id, поэтому его сообщения идут строго по порядку.
- Telegram: `getUpdates` с `allowed_updates = [message, callback_query]`,
  `sendMessage`, `answerCallbackQuery`, `sendChatAction`, `sendVoice`,
  `sendDocument`, `setMyCommands`, `getFile`, `deleteWebhook`.
- Внешние ИИ-сервисы необязательны. Без них работают курс, тренировка,
  повторение, диагностика, прогресс, экспорт и произношение слов из банка.
- Контент занимает около 25 МБ RSS и загружается один раз при старте.
- С локальной речью пик памяти — 865 МБ: piper добавляет ~200 МБ, whisper
  `small.en` в `int8` — ещё ~640 МБ. Модели грузятся лениво, при первом обращении.
- Расшифровка идёт примерно в 1.6 раза медленнее записи: минутный ответ
  обрабатывается около 70 секунд. Замер по числу потоков на этой машине:
  1 — 0.79×, 2 — 1.61×, 3 — 1.68×, 4 — 1.22×, 6 — 0.93× реального времени.
  Больше потоков вредит: CTranslate2 на int8 захлёбывается. Отсюда default 3.

## Контракты

| `LLM_PROVIDER` | нет | `codex`, `openai` или `anthropic`; по умолчанию `openai` |
| `CODEX_BINARY` | нет | по умолчанию `codex` |

| `CODEX_TIMEOUT` | нет | 30–900 с, по умолчанию 180 |
| `OPENAI_API_KEY` | нет | нужен при `LLM_PROVIDER=openai` или `SPEECH_BACKEND=openai` |
| `OPENAI_MODEL` | нет | по умолчанию `gpt-5-mini` |
| `ANTHROPIC_API_KEY` | нет | нужен только при `LLM_PROVIDER=anthropic` |
| `ANTHROPIC_MODEL` | нет | по умолчанию `claude-sonnet-5` |

| `STT_MODEL` | нет | по умолчанию `whisper-1`, только при `SPEECH_BACKEND=openai` |
| `TTS_MODEL`, `TTS_VOICE` | нет | по умолчанию `gpt-4o-mini-tts`, `alloy` |
| `WORKERS` | нет | 1–16, по умолчанию 4 |
| `MAX_VOICE_SECONDS` | нет | 30–900, по умолчанию 300 |
| `DAILY_AI_CALLS` | нет | 5–5000, по умолчанию 120 на человека в сутки |
| `TEAM_OPEN_REGISTRATION` | нет | `1` разрешает вход без приглашения |
| `DATABASE_PATH`, `EXPORT_DIR`, `VOICE_DIR`, `AUDIO_CACHE_DIR` | нет | пути внутри `data/` |
| `LOG_LEVEL` | нет | по умолчанию `INFO` |

Реальные значения только в `.env` с правами владельца; файл исключён из Git.
В логах нет токенов, имён, идентификаторов пользователей и содержимого ответов.

В базе хранится имя из профиля Telegram — оно нужно таблице отдела и
перезаписывается при каждом сообщении, а не накапливается историей. Кто не хочет
быть в таблице, отключается командой `/privacy`; `/forget YES` стирает учебные
данные, оставляя учётку и роль.

### Два независимых контура

Текст и речь переключаются отдельными переменными и ничего друг о друге не знают.
Сборка живёт в `app._build_llm` и `app._build_speech`, остальной код видит один
интерфейс.

**Текст — `LLM_PROVIDER`.** `codex` запускает `codex exec` подпроцессом и работает
по подписке ChatGPT: ключ не нужен, денег не стоит, но ответ занимает 8–12 секунд.
Агент стартует в пустой временной папке под песочницей `read-only`, промпт идёт
через stdin, ответ читается из `--output-last-message`. Разовый сбой запуска
повторяется один раз. `openai` и `anthropic` ходят по HTTP за ключ и отвечают
быстрее. Переключение — одна строка в `.env` и перезапуск, код не меняется.

**Речь — `SPEECH_BACKEND`.** У Codex нет ни распознавания, ни синтеза, поэтому
`local` закрывает голос моделями на этой машине: `faster-whisper` расшифровывает,
`piper` синтезирует, PyAV перекодирует WAV в Ogg/Opus для Telegram — системный
`ffmpeg` не нужен. `openai` возвращает хостинговые Whisper и синтез за ключ.

### Доступ

- Пока в `settings` нет `owner_user_id`, доступ выдаётся только правильному
  `/start <BOT_CLAIM_CODE>`; этот человек получает роль `owner`.
- Дальше вход только по одноразовому коду приглашения — либо, если явно включён
  `TEAM_OPEN_REGISTRATION`, свободно.
- Приглашение создаётся кнопкой «Пригласить коллегу» или «Пригласить админа» на
  экране «📊 Я» владельцем или админом, живёт 14 дней, несёт
  роль и сгорает при использовании. Списание кода атомарно (`BEGIN IMMEDIATE`).
- Обращения к ИИ ограничены `DAILY_AI_CALLS` на человека в сутки; счётчик тоже
  списывается атомарно.

### Схема данных

`PRAGMA user_version` = 3. Таблицы:

| Таблица | Что хранит |
|---|---|
| `settings` | владелец, username бота, отметки экспорта по ключу `last_export:<user_id>` |
| `users` | роль, имя из профиля Telegram, уровень, цель, состояние диалога и его данные, серия, лимит ИИ, флаг участия в таблице |
| `invites` | код, роль, автор, срок, кем использован |
| `placement_answers` | ответы диагностики, сгруппированные по `session_id` |
| `attempts` | каждая попытка: упражнение, пункт, уровень, верно ли |
| `srs_cards` | карточки SM-2: тип, ключ, ease, интервал, повторы, срывы, мастерство, срок |
| `skill_mastery` | мастерство по навыкам и накопленные минуты |
| `messages` | история диалога с наставником |
| `voice_messages` | метаданные записи, расшифровка, разбор, число слов |
| `error_log` | журнал ошибок с категорией и ярлыком паттерна |
| `writing_submissions` | текст, оценки, разбор |
| `pronunciations` | общий кэш платформы: слово, транскрипция, слоги, путь к аудио, `file_id`. Не персонален и не удаляется по `/forget` |
| `sessions` | сессии тренировки и повторения |

### Миграции

Личный бот версии 1 переезжает автоматически при первом запуске:

- `answers` переименовывается в `placement_answers`, ответы сохраняются, к ним
  добавляются `level` и `session_id`, а сама таблица пересобирается с первичным
  ключом `(user_id, session_id, question_id)`. `ALTER TABLE` первичный ключ не
  меняет, и без пересборки вторая диагностика падала бы на нарушении уникальности;
- в `users` доливаются новые колонки, а тому, кто записан в `owner_user_id`,
  проставляется роль `owner`;
- в `voice_messages` добавляются `transcript`, `feedback`, `words`;
- версия 3 добавляет в `pronunciations` колонку `syllables`.

Миграция идемпотентна и не удаляет данные. Проверено на снимке боевой базы и
закреплено тестом `tests/test_storage.py::MigrationTests`.

### Работа с SQLite

Соединение открывается на операцию и закрывается через `Storage.session()`:
`with connection` коммитит, но не закрывает, поэтому голый `connect()` в
долгоживущем процессе течёт. Режим WAL, `busy_timeout` 30 секунд,
`foreign_keys = ON`. Конкурентные счётчики — под `BEGIN IMMEDIATE`.

### Данные на диске

- `data/` исключён из Git одним правилом `.gitignore`, вместе со всеми подпутями.
- Голосовые: `data/voices/<user_id>/<message_id>.ogg`, лимит загрузки 20 МБ,
  права `0600`.
- Кэш синтеза: `data/audio/`, права `0600`. Имя файла — слаг плюс хеш запроса.
  Хеш не учитывает поля тишины: при изменении `PAD_SECONDS` кэш и сохранённые
  `file_id` в `pronunciations` нужно чистить вручную, иначе поедет старый звук.
- Модели локальной речи: `data/models/whisper` (~464 МБ) и `data/models/piper`
  (~61 МБ). Виртуальное окружение `.venv` — ещё ~490 МБ.
- Экспорт: `data/exports/learner-<user_id>.md` и `anki-<user_id>.tsv`, права `0600`.
- `/forget YES` удаляет учебные строки во всех таблицах, файлы голосовых и
  экспорты, но сохраняет учётку и роль.

## Ограничения

- Один токен обслуживается одним процессом: второй экземпляр вызовет конфликт
  `getUpdates`.
- Удалённого бэкапа нет: SQLite, голосовые и экспорты существуют только на этой машине.
- Дорожки не спасают от общего лимита внешнего API: при массовой нагрузке запросы
  к ИИ упираются в квоту провайдера, а не в `WORKERS`.
- Смещение `getUpdates` двигается до обработки: при жёстком убийстве процесса
  уже принятые в дорожку апдейты теряются — Telegram считает их доставленными.
- Внешние ИИ-сервисы оплачиваются отдельно; `DAILY_AI_CALLS` ограничивает число
  обращений, но не их стоимость — длинный разбор дороже короткого.
- `LLM_PROVIDER=codex` расходует лимиты личной подписки ChatGPT, общие на всех
  участников платформы. Это выход за обычное назначение подписки: подходит для
  обкатки владельцем, для постоянной работы отдела предназначен ключ API.
- Локальные модели работают на CPU. Одновременные расшифровки конкурируют за ядра,
  и при нескольких длинных записях подряд очередь растёт линейно.
- Токен, попавший во внешний канал, следует перевыпустить в BotFather.
